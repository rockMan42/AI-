# 飞书交互优化验收清单

本轮修改保留现有 OA、CRM 接口和模拟财务服务。以下用例须在预发飞书端以员工、主管、HR、财务账号完成；本地自动化通过不代表飞书端通过。

| 模块 | 飞书端关键路径 |
|---|---|
| 知识库 | 有答案、无答案、无权限、来源按钮打开原文片段；删除或改版后来源失效提示 |
| 考勤 | 本人、主管所辖、HR 查询；月份、日期、异常状态筛选；越权拒绝 |
| 请假 | 修改草稿、余额不足、审批人变化、提交、重复点击、撤销、审批和驳回 |
| 假期通知 | 发布预览、回执确认、列表、统计刷新、催办、统计报告；重复点击 |
| 物资申领 | 修改草稿、品类规则、OA 超时重试、审批进度和状态更新 |
| 报销 | 多张发票识别和逐张修改、费用补充、出差选择、超标原因、提交、退回重办 |
| CRM | 优先级原因、详情、跟进表单、重复点击、提醒卡片直达跟进 |
| 权限 | 各角色在上述卡片、来源、审批、报告中的最小权限与越权提示 |
| 绩效 | 员工摘要、主管团队分布、HR 公司统计、报告入口与越权拒绝 |
| 业务规则 | 中文编辑表单、审批人姓名、差异预览、人工确认、旧卡片兼容 |
| 主动通知 | 多事项优先级、合并频率、已处理状态更新、重试与失败日志 |

每条路径检查正常、缺字段、空结果、重复消息、重复点击、卡片过期、依赖超时和失败后继续办理。核对数据库只写入一次、卡片状态与业务状态一致，并检查手机端排版与长内容。

启动时只读核对主动通知定时任务是否已注册，缺失会写入错误日志。实际注册沿用现有显式脚本 `scripts/register_notification_cron.py`，以免服务启动时改变调度配置。

性能比较需在相同预发环境留存优化前后日志。可运行 `python scripts/summarize_interaction_metrics.py app.log` 汇总 `feishu_first_feedback`、`feishu_total`、模型与 RAG 阶段的样本数和 P50/P95；同时记录业务失败率与单次请求的模型调用次数。当前没有预发日志，性能结论为“未测量”。知识库最终验收仍按 `docs/rag-acceptance.md` 的真实题库、权限、来源和性能要求执行。
